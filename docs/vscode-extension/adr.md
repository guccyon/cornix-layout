# VS Code 拡張の設計の決定（ADR）

001〜015 は 2026-10-19、016・017 は 2026-10-20（v0.2）、018・019 は 2026-10-21、020・021 は 2026-10-22（v0.4）、022・023 は 2026-10-22（v0.5）に決定。状態は 014 が「018・019 で置き換え」、ほかは「採用」（001 は 015 で実現の仕方を補い、005 は 016 で項目の操作を例外にした。018 の画面と戻す、019 の確認のダイアログは 020 で変えた。016 は 022 で番号の操作とショートカットの追加を除いた）。v0.5 で決めたことの全体は [tasks-v0.5.md](tasks-v0.5.md)。v0.4 で決めたことの全体は [tasks-v0.4.md](tasks-v0.4.md)。v0.2 で決めたことの全体は [tasks-v0.2.md](tasks-v0.2.md)。仕様の全体は [spec.md](spec.md)、リクエストの約束で決めたことは [protocol.md](protocol.md) の「11. 決めたこと」。

| ADR | 決定 | 理由 | 却下した案 |
|---|---|---|---|
| 001 | テキストエディタの補完ではなく、プロファイル丸ごとの専用編集画面（Webview）を主にする | 全ファイルを 1 画面で構造化して見たい。Webview ならアイコンも自由に出せる | テキストでの補完だけ（後から足せる別の入口として残す）。VS Code のカスタムエディタ（1 ファイルに 1 画面） |
| 002 | キー表記の解釈は Ruby のバックエンドで行い、拡張とは JSON-RPC で話す（A 案） | 解釈（`KeycodeNotation` `ShortcutCatalog` など）が Ruby に集まっていて、検証もそのまま使える。拡張単体での利用は今は考えない | B: 候補を JSON で書き出し TypeScript で判定。C: JSON Schema だけ |
| 003 | 拡張はリクエストの約束だけで Ruby と話し、`cornix` を直接叩かない | 将来、母艦以外で使うために TypeScript 版（B）のサーバーに差し替えられるように | 拡張から CLI を直接呼ぶ |
| 004 | 候補の元は `data/*.yaml`、「この入力ならこの候補」の共通テストをデータで書く | Ruby と TypeScript の二重実装の食い違いを防ぐ | 各実装に別々のテスト |
| 005 | 画面の変更は未保存（dirty）として持ち Ctrl+S で保存する | 直感的で、元に戻す・未保存の表示を VS Code に任せられる | 変えたらすぐ書く（VS Code の設定画面と同じ） |
| 006 | 書き戻しは変わった値の部分だけを書き換える | 手で書いたコメント・並び・注記を壊さない | YAML を作り直す |
| 007 | 外でファイルが変わったら、未保存がなければ読み直し、あればどちらを残すか聞く | Claude が並行して編集するのが普通の使い方 | 常に読み直す |
| 008 | 入口はコマンドとアクティビティバー | ディレクトリ全体を開く画面なので、特定のファイルに結び付けない | `.cornix.yml` を開くとこの画面 |
| 009 | 2 ペイン（上にキーボード図、下に編集画面）。物理配置は Cornix 専用として拡張に固定 | 図から該当項目へ飛べて直感的。対象は Cornix だけ | 編集のできるリッチな図（それなら Vial）。物理配置をデータファイルに |
| 010 | アイコンは割り当て済みのキーを優先。自分のショートカットはアイコンなし | 一覧での見分けやすさがいちばん効く。自分の定義はアプリが分からない | 候補の行を先に。定義に `icon:` を書く（将来の余地として残す） |
| 011 | 素材は Simple Icons → Material Icon Theme → 自前のバッジ。対応表は `data/` に ID だけ、画像は拡張に同梱 | フリーライセンスを優先。アプリの一覧と同じ場所で漏れをテストでき、画像とライセンスは画面側にまとまる | cornixhub の画像。対応表を拡張だけに持つ |
| 012 | 検証は画面では onchange、テキストでは波線 | 入れたその場で間違いに気づける | 保存時だけ |
| 013 | 置き場所はこのリポジトリの `editors/vscode/`。配布は自分用 .vsix | リクエストの約束を 1 つの PR で両側変えられ、`data/` と共通テストをそのまま使える。大きくなったら `git subtree split` で切り出せる | 別リポジトリ。Marketplace で公開 |
| 014 | ~~実機への書き込みは拡張に入れない~~（v0.4 で 018・019 に置き換え） | 利用者の同意なしに書き込まないというリポジトリの方針。読むだけのコマンドだけ入れる | apply / restore を入れる |
| 015 | 専用編集画面（ADR 001）は、プロファイルを 1 つの仮想ドキュメント（`cornix-profile:`）に見立てたカスタムエディタとして作る | VS Code が dirty の印・Ctrl+S・閉じるときの確認を面倒みるのはカスタムエディタだけ。仮想ドキュメントにすれば「1 ファイルに 1 画面」にならず、プロファイル丸ごとの画面のまま乗せられる（ADR 005 を VS Code の仕組みで実現できる） | ふつうの Webview パネルで dirty・保存・元に戻すを自前で作る |
| 016 | 項目の追加・削除・名前の変更（位置の名前の変更も）は未保存に積まず、確認のダイアログのあとすぐファイルに書く。未保存の変更があれば先に保存を促す。サーバーは書き換えを返すだけ（`profile/planItemEdit`）で、拡張が 1 つの `WorkspaceEdit` で当てて保存する | ファイルの作成・削除・改名を未保存の変更に混ぜると、参照の置き換え・compile の照合・外での変更の当て直しが複雑になる。中身の編集はこれまでどおり未保存（ADR 005） | 項目の操作も未保存に積み Ctrl+S でまとめて書く。サーバーが直接ファイルを書く |
| 017 | 未保存の変更は当てる順の 1 本の並びにし、並び（マクロの手順・キー、コンボのキー）の中を指す Address は前の変更を当てたあとの位置で数える。並びの外の値は同じ場所の前の変更をその位置で置き換えて畳む | 挿入・削除・移動のあとの位置を一意に決められ、サーバー・ホスト・画面が同じ規則で当てられる。値だけの変更は v0.1 と同じく最後の値が効く | Address ごとの最後の値だけを持つ（v0.1 の形。並びの操作を表せない）。並びを丸ごと置き換える（コメントや書式を保てない。ADR 006） |
| 018 | 実機の操作（比べる・反映・戻す）を拡張に入れる。`cornix serve` とは別のプロセス `cornix serve --device` で、同じ枠の JSON-RPC の `device/*` として行う | Vial を開かずに編集から反映までを 1 画面で済ませたい（v0.3 を使った利用者の要望）。実機を全部読むと BLE で約 10 秒かかるので、1 つずつ処理する編集のサーバーと分けて候補や検証を止めない。中身は CLI・MCP と同じユースケース（`DeviceDiff` / `DeviceApply` / `DeviceRestore`）を使う | 同じプロセスの別スレッド（状態の共有と止め方が複雑）。拡張から CLI を呼ぶ（y/N の確認と出力の文を読むことになり、ADR 003 に反する）。実機から取り込む pull も入れる（decompile が設定を書き直すので、注記や未保存の変更との関係が重い。次の版以降） |
| 019 | 書き込みは設定 `cornix.device.allowWrites`（既定 `false`）で許したときだけ。拡張はそのときだけサーバーを `--allow-writes` で起動し、なければサーバーが断る。毎回、差分と件数を見せる確認のダイアログを出し（省けない）、token で比べたときの計画と同じことを確かめ、書く前にバックアップを取り、書いたあと読み直す | 利用者の同意なしに書き込まないというリポジトリの方針（ADR 014 の理由）を、画面からの操作でも守る。開発中・テスト中の誤った書き込みを拡張とサーバーの二重で止める。差分・token・バックアップ・読み直しは CLI・MCP の apply と同じ流れ | 既定で許す（誤操作とテストでの書き込みを止められない）。確認のダイアログに「次から聞かない」を付ける。開いたときや保存したときに自動で比べる（10 秒かかり BLE をふさぐ） |
| 020 | 実機の操作は反映だけにし、プレビュー → 確定の 1 つの流れにする。入口は編集フォームの一番下の畳める節「デバイス転送」とコマンド「Cornix: 実機に反映…」。違いは編集画面に重ねたモーダル（図に橙の枠・タブに件数・一覧）に出し、モーダルの「確定」で書く（019 の確認のダイアログはこれに置き換える）。検証のエラーがあるあいだは「反映のプレビュー…」を押せず（理由をボタンの横に出し、コマンドからでも実機を読む前に止める）、確定は書き込みを許していないとき・検証のエラーがあるとき・プレビューのあとで設定ファイルが変わったときは押せない。モーダルの間は編集画面を操作できない。戻す（バックアップから）は拡張に入れない（device のサーバーの `device/backups`・`device/compareBackup`・`device/restore` は残す） | Tetsuro が v0.4 の .vsix を見て（2026-10-22）: 図の上の 3 つのボタンと印がごちゃごちゃする。反映はしょっちゅう使わない。比べるのは反映の前に違いを見るためだけ。戻すは設定ファイルを Undo や git で戻して反映し直せば足り、バックアップから戻すなら設定ファイルで確かめながらにしたい。反映の最中にソースを変えさせたくない。検証のエラーがあるまま書きたくないし、エラーがあるのに実機を読んで待たせたくない | 図の上に比べる・反映・戻すのボタンと「実機: 同じ／違う」の印（018 の最初の形）。プレビューを編集画面の図に重ねて出す（編集中の図と混ざり、反映の最中に編集できてしまう）。確定のあとにさらに VS Code のモーダルで確かめる（プレビューで違いと書き込み先を見ているので二度手間）。別のマシンで変えた実機の内容を選んで取り込む（リストアよりマージに近い。roadmap.md の候補） |
| 021 | 構造検証の問題が読めない値（解析できないキーコード）だけなら、エディタのサーバーはその値を `NoKey` として読み続け、`status: "ok"` で返す。画面は編集フォームを出してその欄をエラーにし、構造の error と意味検証の結果（警告など）をまとめて出す。項目の操作・compile・実機への反映は今までどおり止める。検証の結果の行は生のファイルを開かずに編集フォームのその欄へ移る | Tetsuro が v0.4 の .vsix を見て（2026-10-22）: エラーと警告が両方あるのに警告が出ない（構造のエラーで意味検証が走らない）。「ファイルを開く」で生のファイルを直すと画面とずれる。編集フォームのそのキーにフォーカスを当てたい | 今の 2 段のまま「エラーを直すと警告も出ます」と添える（B 案）。読めない値の欄を `value: null` にする（書いてある表記が見えず直しにくい） |
| 022 | 取り出す・未使用にする・番号の変更（`index:` の書き換えと削除。マクロ・タップダンスの番号の参照の書き換えを含む）とショートカットの追加は、016 の例外にして未保存の変更に積む（元に戻す・やり直し、Ctrl+S で保存）。サーバーは今の未保存の変更を当てた状態で決めた Change の並びを返し（`profile/planItemEdit` の `changes`）、拡張はそれを 1 つの編集として積む。ファイルの作成・削除・改名を伴う操作は 016 のまま | Tetsuro（2026-10-22）: 同梱のショートカットを選ぶとすぐファイルに書かれるのをやめ、編集中はメモリに持って undo / redo しながら Ctrl+S で保存したい。これらはどれも既存のファイルの値の書き換え（と行の追加・削除）だけで、016 が避けたファイルの作成・削除・改名を伴わないので、今の未保存の変更の仕組み（ADR 005・017）にそのまま乗る | ショートカットの追加だけを未保存にする（操作によって保存のされ方が違ってしまう）。追加・削除も含めてすべて未保存にする（保存のときにファイルを作る・消すしくみが要り、参照の置き換えや外での変更の当て直しが複雑になる。016 の理由） |
| 023 | 未使用の項目（`index:` のないファイル。#85）は使っているものと並べず、レイヤーの「＋」と節の「追加」の一覧の「未使用（N）」から取り出す。取り出すと末尾の番号で使い始め（未使用のまま開いて編集はしない）、並べ替えは番号の変更・入れ替え（1 つの番号の選択）で行う。項目の操作は見出しの「…」1 つにまとめ、状態に合うものだけ出す | Tetsuro（2026-10-22）: 未使用のレイヤーがいくつできるか分からないので、使っているものと並べずにしまっておきたい。ボタンを並べて操作の入口を増やすのは避け、そのときに要るものだけ見せたい。編集するならいずれかの番号に割り当てたいので、未使用のまま取り出せる必要はない。番号は一旦末尾でよく、あとで並べ替えられれば足りる | 未使用のまとまりを各節やレイヤーのタブに薄く並べて、そのまま編集できるようにする（#105 の最初の案。数が増えると邪魔）。取り出すときに番号を選ばせる（たいていは末尾でよく、一手増える）。番号の変更と入れ替えを別の操作にする |
