# VS Code 拡張の仕様

cornix-layout のプロファイル（設定ディレクトリ）丸ごとを 1 画面で構造化して見せ、補完つきで編集できる VS Code 拡張を作る。
仕様は 2026-10-19 の相談ですべて決まり、自分用の v0.1（レイヤーと QMK 設定）と v0.2（すべての設定ファイル。[tasks-v0.2.md](tasks-v0.2.md)）、v0.3（使い勝手。[tasks-v0.3.md](tasks-v0.3.md)）ができている。v0.4（実機とつなぐ。[tasks-v0.4.md](tasks-v0.4.md)）は設計が決まった。決定の理由は [adr.md](adr.md)、版の割り振りは [roadmap.md](roadmap.md)、
バックエンドとのやりとりは [protocol.md](protocol.md)。

## 背景と目標

キーマップの編集はふだん Claude 経由だが、素早く手で直したいときに、候補から選びながら編集できるようにしたい。

- 対象: guccyon/cornix-layout の設定ファイル（`layers/` `macros/` `tap_dance/` `combos/` `shortcuts.yaml` `settings/qmk_settings.yaml` `metadata.yaml` `position_map.yaml`）
- とくに助けたいもの: 同梱のショートカット（`data/shortcuts/` の 27 アプリ、`Shortcut('アプリ:カテゴリ:ラベル')`）と、それを元にしたマクロ（`macros/` の `preset:`）
- 線引き: リッチにしすぎない。それ以上の操作は Vial を使う
- 利用者: まずは作者本人。母艦（cornix の Ruby が動く Mac）で使う

## 仕様

プロファイル丸ごとを扱う専用の編集画面（Webview）を、Ruby のバックエンドと JSON-RPC でつなぐ。

### 画面

- 入口: コマンド「Cornix: プロファイルを開く」と、左のアクティビティバーのアイコン。`profiles/` に複数あるときは開くときに選ぶ（`.cornix.yml` の既定を初期値に）
- 2 ペイン: 上に `position_map` をキーボードの形で描いた図、下に構造化した編集画面。図のキーをクリックすると下の該当項目へ移動する
- キーボード図の物理配置（キーの座標）は Cornix 専用として拡張に固定で持ち、`position_map.yaml` の論理位置と組み合わせる
- 下はレイヤーの欄と、QMK 設定・マクロ・タップダンス・コンボ・ショートカット・メタデータの節を並べ、選んでいるレイヤーを上下で共有する。
  最初に開いたときはレイヤー以外の節を畳み、summary に `▶` / `▼` の印を付ける（v0.3。描き直しでは開閉を保つ）
- レイヤーの欄の上の「レイヤーごと / キーごと」の切り替え（v0.4。issue #84）。既定はレイヤーごと（選んでいるレイヤー 1 枚の欄）。選んだ並べ方は描き直し・外での変更による読み直し・タブを裏に回したあとも保つ。
  - キーごと: グループの並び（`left_hand.row0`〜`thumb_keys`、`right_hand`、エンコーダの左回し・押し込み・右回し）と見出しはレイヤーごとと同じで、
    位置ごとに位置の名前（紫）の下へ、ファイルのあるレイヤーを index の順に `番号 名前` と入力欄の行で並べる。あるキーが各レイヤーでどう割り当てられているかを比べ、その場で直すため
  - 行の入力欄・候補・検証・注記・割り当てを消す操作・未保存の変更はレイヤーごとの欄と同じ部品（変更はそのレイヤーのファイルの `Change`）。書いていない位置は空欄で、入れると行を足す。`KC_TRNS` の説明にはレイヤー 0 の値
  - 図で選んでいるレイヤーの行を強調する。図のキーを押すと、その位置のまとまりの選んでいるレイヤーの行へ移ってフォーカスする。ほかのレイヤーの行を選ぶと、図では同じ位置のキーを選ぶ。
    レイヤーを選び直しても下の欄は作り直さない（スクロールと打ちかけを残す）
  - 「▽ と空欄を畳む」: `KC_TRNS` と書いていない行を隠す（図で選んでいるレイヤー・選んでいる行・未保存の行・フォーカスのある行は残す）。既定は畳まない
- レイヤーの追加と削除（v0.4。issue #84）: レイヤーの並びの末尾の「＋」で、空いている番号（0〜9）と名前を選んで `layers/{番号}_{名前}.yaml` を作る（足したら選ぶ。名前はほかのレイヤーと同じでもよい）。
  レイヤーごとの並べ方のときのレイヤーの見出しの「レイヤーを削除」で（キーごとではどれが消えるか分かりにくいので出さない。消すのは番号で指したレイヤー）、確認のダイアログにそのレイヤーを指すレイヤー操作（`MO(n)` など。16bit 値で数える）の数を出してからファイルを消す。
  どちらも項目の操作と同じく確認のあとすぐファイルに書く（未保存の変更には積まない。[protocol.md](protocol.md) の 14.9）
- レイヤーのタブ: 保存済みの中身に検証の問題（そのレイヤーのファイルの diagnostics）があれば、タブに点（黄は警告、赤はエラー）を付け、ツールチップに件数と最初の 3 件の文を出す（v0.4。issue #84）。
  未保存の変更の問題は欄の印だけで、タブには出さない
- 図の上の「位置の名前」のトグルボタン（固定）と、ボタンにマウスを載せている間・Alt を押している間（一時）で、割り当ての代わりに位置の名前（`position_map.yaml` の名前）を紫（`--vscode-charts-purple`）で見せる。下のペインのレイヤーの欄のラベル（位置の名前）も同じ紫（v0.2）。
  ボタンの説明と、表示中に図の下に出す 1 行で、名前の出所が `position_map.yaml` で、そこを変える（表示中にキーを押して変える）とラベルが変わることを伝える（v0.3）
- v0.3 の図の上の「全レイヤー」のトグル（各キーの面にレイヤーごとの値を小さな行で並べる）は v0.4 でやめ、下の欄の「キーごと」に置き換えた（issue #84。求めていたのは図ではなく下の欄の全レイヤーの表示だった）
- コンボ: 図の上にコンボの番号のボタンを並べ、押す（固定）かマウスを載せている（一時）間、そのコンボのトリガーのキーを割り当てた位置だけを強調する（ほかは少し沈める。同時に 1 つ）。
  トリガーは位置ではなくキーコードなので、今のレイヤーでそのキーコード（16bit 値）を割り当てた位置を探す（`KC_TRNS` はレイヤー 0 の値。未保存の変更も重ねる）。
  ボタンの説明にコンボの名前・トリガー・出すキー。押せないコンボ（下の「範囲」）のボタンには ⚠（v0.3。⚠ は保存済みの値で決まり、未保存の変更では変わらない）
- 図からキーを選ぶ状態（v0.3。`App#pickKey`）: コンボの「図から選ぶ」から入り、図の上に「キーを押して選ぶ（Esc で戻る）」と点線の外枠を出す。押したキーの今のレイヤーの表記を返して抜ける。
  Esc か、もう一度ボタンを押すと選ばずに抜ける。書いていない位置は選べない
- 画面の言語は日本語だけ

### 作り

- Ruby のバックエンド: `cornix` に常駐のサブコマンドを足し、標準入出力の JSON-RPC で話す。リクエストの例は、プロファイルを構造で読む、候補を引く、変更を書き込む、保存前の状態で検証する
- 拡張はこのリクエストだけで Ruby と話し、`cornix` コマンドを直接叩かない
- 保存: 画面の変更は未保存（dirty）の状態として持ち、Ctrl+S で保存する。元に戻す・未保存の表示は VS Code の仕組みに乗せる
- 書き戻しは YAML を作り直さず、変わった値の部分だけを書き換える（手で書いたコメント・並び・注記を壊さない。`Storage::ConfigEditor#update_fields` と同じ考え方）
- 外での変更: 開いている間に Claude やテキストエディタがファイルを変えたら、未保存の変更がなければ黙って読み直し、あればどちらを残すか聞く
- `cornix` の場所: 設定 `cornix.path`。既定はワークスペースの `bin/cornix`、なければ PATH。見つからなければ設定を開くボタン付きで知らせる
- Webview: 素の TypeScript。部品が増えたら Lit などの軽いライブラリを足す。ビルドは esbuild、テストは vitest と @vscode/test-electron（仮の決め。作り始めてから変えてよい）

### アイコン

- 優先は割り当て済みのキーのアイコン（図や一覧での見分けやすさ）。候補の行のアイコンはその次
- 同梱のショートカットはアプリのアイコン。`preset:` で作ったマクロを割り当てたキーにも元のアプリのアイコン
- `shortcuts.yaml` の自分のショートカットはアイコンなし
- 対応表: `data/` の別ファイルにアプリ名 → アイコン ID（例 `simple-icons:figma`）だけを持ち、全アプリに対応があるかをテストで確かめる。SVG とライセンス表記は拡張に同梱
- 素材: [Simple Icons](https://simpleicons.org/)（CC0。27 アプリ中 15）→ [Material Icon Theme](https://github.com/material-extensions/vscode-material-icon-theme)（MIT。VS Code・Word・PowerPoint）→ 残り 9 個（CleanShot, Clip Studio, Excel, Fusion 360, Illustrator, Photoshop, Premiere, Slack, Windows）は頭文字の色付きバッジを自前で作る

### 検証

- 編集画面: 値を入れたとき（onchange）に検証し、入力欄をエラーにしてメッセージを添える。未対応キーは警告
- 原因が別の項目にあるエラー（消したマクロへの参照など）は、参照している側に出す
- テキストで開いているとき: 同じ結果を波線で出す（v0.2。snapshot の `diagnostics` を `DiagnosticCollection` に入れる。未保存の変更の検証の結果は出さない）
- 仕様を決めたときに足りなかったもの（どちらも v0.1 で足した）: 保存前の状態で検証する入口（`profile/validate`）、波線のための行と列（Diagnostic の `range`）

### 範囲

- エディタから実行できるのは compile / validate / status（読むだけ）。実機への書き込み（apply / restore）は v0.3 までは入れない（ADR 014）。
  v0.4 で「比べる」「反映」「戻す」を入れる（下の「実機とつなぐ（v0.4）」。ADR 018・019）
- 項目（マクロ・タップダンス・コンボ・ショートカット）の追加・削除・名前の変更と、レイヤーの名前の変更は v0.2 で入れた（レイヤーの追加と削除は v0.4。上の「画面」）。確認のダイアログのあとすぐファイルに書き（未保存の変更には積まない）、名前の変更は `cornix rename` と同じく参照をテキストで置き換えて前後の compile の結果を照合する
- preset を手順に展開（v0.3）: マクロの `preset:` の横の「手順に展開」で、`preset:` の行を同梱の定義（`data/shortcuts/` の `macro: true` の項目）の `sequence:` に置き換える。
  ほかの行は変えず、書くキーは decompile の正規形。1 シーケンスの定義（修飾キーを押す → キー → 離す）も展開できる。項目の操作と同じく確認のダイアログのあとすぐ書き、前後の compile の結果（16bit 値）が同じでなければ書かない。
  `name:` のないマクロには名前が変わらないよう `name:` を足す。`preset: X # コメント` の行末のコメントは消える
- 同梱ショートカットを自分のものにコピー（v0.3）: ショートカットの節の「同梱からコピー」で、同梱の選択（下の「入力と補完」）で選んだものを `shortcuts.yaml` に足す（名前はラベル、値は同梱の表記。
  同じ名前があれば追加の欄をエラー付きで開いて名前を聞く）。コピーしても既存の参照（`Shortcut('アプリ:カテゴリ:ラベル')`）は書き換えない
- 押せないコンボ（v0.3）: トリガーのキー（`KC_NO` を除く）がすべてそろうレイヤーが 1 つもないコンボ。レイヤーごとに、位置の割り当てとエンコーダのプッシュのキーコード（`KC_TRNS` の位置はレイヤー 0 の値）を集めて見る。
  意味検証の警告「押せないコンボです」（validate にも出る。[validation.md](../validation.md)）にし、コンボの節の一覧の行と図のコンボのボタンに ⚠（詳細の説明は問題の欄に出るサーバーの警告に任せる）。トリガーが `KC_NO` だけのコンボ（作ったばかり）は警告しない
- 置き場所はこのリポジトリの `editors/vscode/`。CI は変更したパスで Ruby と Node を分ける
- 配布は、まず自分用に手元で .vsix を入れる

## 実機とつなぐ（v0.4）

設計は [tasks-v0.4.md](tasks-v0.4.md)、約束は [protocol.md](protocol.md) の 14。**状態: 設計（実装はこれから）。**

- 図の上に「比べる」「反映」「戻す」のボタンと、印「実機: 同じ／違う N 件／未確認」（状態バーにも）。コマンド「Cornix: 実機と比べる／反映／戻す」
- 比べる（読むだけ）: 保存済みのプロファイルを compile し、実機を読んで差分を出す。違うキーを橙の枠で囲み、ほかのレイヤーの違いはタブに点。差分は畳める節「実機との差分」に「場所: 実機の値 → このプロファイルの値」で並べ、行から欄へ移れる
- 反映: 未保存の変更があれば先に保存を促す → 比べる → 確認のダイアログ（件数・警告・キーボード名。モーダル。毎回）→ バックアップ → 書く → 読み直して検証。差分がなければ何も書かない
- 戻す: バックアップの一覧から選び（既定は最新）、反映と同じ確認の流れ
- 書き込みは設定 `cornix.device.allowWrites`（既定 `false`）が `true` のときだけ。比べるはいつでも使える
- 印は自動では更新しない（実機を読むのに約 10 秒かかる）。比べる・反映・戻すのあとに更新し、保存したら「未確認」
- 実機が使えないとき（macOS 以外・ブリッジが未ビルド・つながっていない）は、押したときに理由と直し方を出す
- 実機の操作は `cornix serve --device`（編集のサーバーとは別のプロセス）が行う。テストはすべて偽の実機

## 入力と補完

キーを入れる場所はどこも同じ「キー入力欄」を使い、ファイルの種類と項目ごとに「出す候補の種類」と「並び順」だけを変える。
版の割り振りはたたき台で、版ごとに足したり削ったりする。

### キー入力欄の候補の種類

| 種類 | 例 | 出どころ | 版 |
|---|---|---|---|
| 基本キー・修飾キー単体 | `A` `;` `Enter` `F12` `LShift` | `data/keycodes.yaml` と `data/aliases.yaml` | v0.1 |
| 修飾キー式 | `Shift + Command + P` | `KeycodeNotation` | v0.1（打つ）・v0.2（組み立て欄） |
| レイヤー操作 | `MO(1)` `TG(3)` `OSL(9)` | `KeycodeCodec` | v0.1 |
| レイヤー＋キー・Mod-Tap | `LT(2, Escape)` `RSFT_T(Up)` | `KeycodeCodec` | v0.2（組み立て欄） |
| マクロ・タップダンス | `Macro('Bracket Pair')` | そのプロファイル | v0.1 |
| 自分のショートカット | `Shortcut('前のタブへ')` | `shortcuts.yaml` | v0.1 |
| 同梱のショートカット | `Shortcut('VS Code:基本操作:コマンドパレット')` | `data/shortcuts/`（アプリ → カテゴリ → ラベルでも辿れる） | v0.1 |
| メディア・マウス・特殊 | `VolumeUp` `KC_NO` `KC_TRNS` | `data/keycodes.yaml` | v0.1 |
| 直接の値 | `0x7E40` | — | v0.1（`0x` と打ったときだけ） |

- `data/dangerous_keycodes.yaml` のキーは出さない。`data/unsupported_keycodes.yaml` のキーは警告の印を付けて下に並べる
- 検索は正規の名前・別名・QMK 名・記号そのもの・ショートカットの日本語ラベルとアプリ名に当てる。当てはまり方は完全一致 → 前方一致 → 部分一致 → あいまい一致の順に上から並べる
- あいまい一致（v0.3）: 前方一致・部分一致に当たらないとき、query の文字を順に含む（間を飛ばしてよい）ものを出す（`lbr` → `KC_LBRACKET`）。大文字小文字・`_`・空白は区別しない。飛ばした文字の少ないものを上に。
  離れた文字にも当たる（`Tab` → `|` (VerticalBar) など）が、下に並ぶのでそのままにした
- よく使うキーを上に（v0.3）: 当てはまり方が同じ候補の中で、そのプロファイルの全レイヤー・エンコーダ・マクロ・タップダンス・コンボで使っている回数（16bit 値で数える。`KC_NO`・`KC_TRNS` は数えない）の多いものを上にする（同じ回数なら今の並び）。
  context ごとに上に出すもの（下の「上に出すもの」。`data/keycode_categories.yaml` の `contexts`）は今までどおり先
- 同梱のショートカットの導線（v0.3）: 候補の一覧のいちばん下に「同梱から選ぶ…」を置き、マクロの `preset:` と同じ階層の選択（アプリ → カテゴリ → ラベル、アイコン付き）を開いて `Shortcut('アプリ:カテゴリ:ラベル')` を入れる。
  手順の定義しかない `macro: true` の項目は出さない。出すのは `Shortcut(...)` を書ける欄（レイヤーのキー・エンコーダ・タップダンスの動作・コンボの出すキー）だけ
- 選んだ候補は decompile の正規形で書く。手で打った表記は解釈できればそのまま残す
- キーにマウスを載せると、何に解釈されるか（Shortcut の中身、マクロの手順など）を出す（v0.1）
- 2 役のキー（`LT` など）はタップとホールドを上下に分けて描く
- レイヤー操作も同じ形で、下の帯にレイヤーを番号（`L3`）で描く。`MO` は面を空けて帯だけ、ほかは面に操作名（`TG` など）、`LM` は面に修飾キーの記号。
  レイヤーの名前は図には出さず（任意の名前で長くなりがちなため）、説明で見せる。エンコーダの帯でも同じ
- 何もしないキー（`NoKey`）は空白で描く（✕ や x は文字のキーと見間違えるため）。書いていないキー（compile では `NoKey` になる）も同じ見た目（枠はあって中は空白。v0.2 の点線の枠は背景を抜いていて図から消えて見えたので v0.3 で変えた）。
  割り当てを消した欄にも placeholder（v0.2 の `（なし）`）を出さず空白にする（v0.3）
- 矢印キー（`KC_UP` / `KC_LEFT` / `KC_RIGHT` / `KC_DOWN`）は図・説明・マクロの手順の行で `↑` / `←` / `→` / `↓` と描く（修飾キー式も `⌥↑` など。v0.3）。書く表記（`Up` など）は変えない
- `KC_TRNS` のキーには、レイヤー 0 の同じ位置のキーを薄く描き、説明に「レイヤー 0 の値」と書く（v0.2。どのレイヤーが有効かは実行時に決まり、ふだんはベースに落ちるため）
- タップダンスは、割り当てのある動作の数でキーの面を窓に分けて描く（1 つは面全体、2 つ・3 つは横幅いっぱいの窓を上から順に重ね、4 つは 2×2。順はタップ・ホールド・ダブルタップ・タップホールド。
  後ろの窓ほど背景を少し濃く）。エンコーダの帯では窓にせず、タップの文字と残りの数（`+3`）を並べる。定義が見つからないものは `TD` の印
- マクロには `M`（橙、`--vscode-charts-orange`。v0.1 の紫は位置の名前の色にしたので v0.2 で変えた）、自分のショートカット（`shortcuts.yaml`）には `★`（緑）の印を右上に付ける。アイコンのあるもの（同梱のショートカット・`preset:` のマクロ）には付けない。
  印の意味は説明と読み上げで、窓の中身は読み上げ（と説明の「タップ: …」などの動作の行）で伝える

### ファイルの種類ごと

| ファイル | 項目 | 候補 | 上に出すもの | 版 |
|---|---|---|---|---|
| `layers/` | 各キー | 全部 | 基本キー | v0.1 |
| `layers/` | エンコーダの押し込み・回転 | 全部 | メディア・マウスホイール・音量 | v0.1 |
| `layers/` | 注記 | 1 行の文字 | — | v0.2 |
| `macros/` | tap / down / up のキー | 基本キー・修飾キー・メディア（「すべて出す」の切り替え付き） | — | v0.2 |
| `macros/` | delay / text | 数値（ミリ秒）・ASCII の文字 | — | v0.2 |
| `macros/` | `preset:` | 手順の定義がある同梱ショートカット（アイコン付きの階層選択）。「手順に展開」で手順に置き換える | — | v0.2・v0.3（展開） |
| `tap_dance/` | 4 つの動作 | 全部（自分自身への参照は除く） | 基本キー・レイヤー操作 | v0.2 |
| `tap_dance/` | tapping_term | 数値（QMK 設定の値を薄く添える） | — | v0.2 |
| `combos/` | 同時に押すキー（最大 4） | 基本キー・修飾キー。「図から選ぶ」で図のキーの今のレイヤーの表記も（NoKey のキーがあればそこを置き換え、なければ末尾に足す） | ベースレイヤーにあるキー | v0.2・v0.3（図から） |
| `combos/` | 出すキー | 全部 | マクロ・基本キー | v0.2 |
| `shortcuts.yaml` | 値 | 全部から `Shortcut(...)` を除く。「同梱からコピー」で同梱のものを足す | — | v0.2・v0.3（コピー） |
| `settings/qmk_settings.yaml` | 各設定 | 整数は数値、真偽値はチェックボックス（説明と既定値付き） | — | v0.1 |
| `metadata.yaml` | — | 読むだけで表示（入れ子の Hash・配列は表の中の表） | — | v0.1 |
| `position_map.yaml` | 位置の名前 | 1 語の名前（英数字と `_` `-`、同じグループで重ならない）。レイヤーの欄のラベルの ✎ か、位置の名前の表示中に図のキーから。全レイヤーの `mapping` のキーもまとめて書き換える | — | v0.2 |

- `layers/` の各キーの候補の並びで「上に出すもの」の基本キーには、修飾キー単体（`LShift` など）を含めない（候補には出るが、並びは上にしない）
- マクロのキーを絞るのは推定に基づく。読み込みはどのキーコードも受け付けるが、レイヤー操作や参照をマクロで送っても期待どおり動かないと考えられる
- レイヤー操作の候補にはレイヤーの名前を添える（`MO(1)  Symbols`）
- QMK 設定の説明文は `data/qmk_settings.yaml` に足す（今は名前と型だけ）
