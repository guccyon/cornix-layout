# VS Code 拡張の設計の決定（ADR）

001〜015 は 2026-10-19、016・017 は 2026-10-20（v0.2）に決定。状態はどれも「採用」（001 は 015 で実現の仕方を補い、005 は 016 で項目の操作を例外にした）。v0.2 で決めたことの全体は [tasks-v0.2.md](tasks-v0.2.md)。仕様の全体は [spec.md](spec.md)、リクエストの約束で決めたことは [protocol.md](protocol.md) の「11. 決めたこと」。

| ADR | 決定 | 理由 | 却下した案 |
|---|---|---|---|
| 001 | テキストエディタの補完ではなく、プロファイル丸ごとの専用編集画面（Webview）を主にする | 全ファイルを 1 画面で構造化して見たい。Webview ならアイコンも自由に出せる | テキストでの補完だけ（後から足せる別の入口として残す）。VS Code のカスタムエディタ（1 ファイルに 1 画面） |
| 002 | キー表記の解釈は Ruby のバックエンドで行い、拡張とは JSON-RPC で話す（A 案） | 解釈（`KeycodeNotation` `ShortcutCatalog` など）が Ruby に集まっていて、検証もそのまま使える。拡張単体での利用は今は考えない | B: 候補を JSON で書き出し TypeScript で判定。C: JSON Schema だけ |
| 003 | 拡張はリクエストの約束だけで Ruby と話し、`cornix` を直接叩かない | 将来、母艦以外で使うために TypeScript 版（B）のサーバーに差し替えられるように | 拡張から CLI を直接呼ぶ |
| 004 | 候補の元は `data/*.yaml`、「この入力ならこの候補」の共通テストをデータで書く | Ruby と TypeScript の二重実装の食い違いを防ぐ | 各実装に別々のテスト |
| 005 | 画面の変更は未保存（dirty）として持ち Ctrl+S で保存する | 直感的で、元に戻す・未保存の表示を VS Code に任せられる | 変えたらすぐ書く（VS Code の設定画面と同じ） |
| 006 | 書き戻しは変わった値の部分だけを書き換える | 手で書いたコメント・並び・注記を壊さない | YAML を作り直す |
| 007 | 外でファイルが変わったら、未保存がなければ読み直し、あればどちらを残すか聞く | Claude が並行して編集するのが普通の使い方 | 常に読み直す |
| 008 | 入口はコマンドとアクティビティバー | ディレクトリ全体を開く画面なので、特定のファイルに結び付けない | `.cornix.yml` を開くとこの画面 |
| 009 | 2 ペイン（上にキーボード図、下に編集画面）。物理配置は Cornix 専用として拡張に固定 | 図から該当項目へ飛べて直感的。対象は Cornix だけ | 編集のできるリッチな図（それなら Vial）。物理配置をデータファイルに |
| 010 | アイコンは割り当て済みのキーを優先。自分のショートカットはアイコンなし | 一覧での見分けやすさがいちばん効く。自分の定義はアプリが分からない | 候補の行を先に。定義に `icon:` を書く（将来の余地として残す） |
| 011 | 素材は Simple Icons → Material Icon Theme → 自前のバッジ。対応表は `data/` に ID だけ、画像は拡張に同梱 | フリーライセンスを優先。アプリの一覧と同じ場所で漏れをテストでき、画像とライセンスは画面側にまとまる | cornixhub の画像。対応表を拡張だけに持つ |
| 012 | 検証は画面では onchange、テキストでは波線 | 入れたその場で間違いに気づける | 保存時だけ |
| 013 | 置き場所はこのリポジトリの `editors/vscode/`。配布は自分用 .vsix | リクエストの約束を 1 つの PR で両側変えられ、`data/` と共通テストをそのまま使える。大きくなったら `git subtree split` で切り出せる | 別リポジトリ。Marketplace で公開 |
| 014 | 実機への書き込みは拡張に入れない | 利用者の同意なしに書き込まないというリポジトリの方針。読むだけのコマンドだけ入れる | apply / restore を入れる |
| 015 | 専用編集画面（ADR 001）は、プロファイルを 1 つの仮想ドキュメント（`cornix-profile:`）に見立てたカスタムエディタとして作る | VS Code が dirty の印・Ctrl+S・閉じるときの確認を面倒みるのはカスタムエディタだけ。仮想ドキュメントにすれば「1 ファイルに 1 画面」にならず、プロファイル丸ごとの画面のまま乗せられる（ADR 005 を VS Code の仕組みで実現できる） | ふつうの Webview パネルで dirty・保存・元に戻すを自前で作る |
| 016 | 項目の追加・削除・名前の変更（位置の名前の変更も）は未保存に積まず、確認のダイアログのあとすぐファイルに書く。未保存の変更があれば先に保存を促す。サーバーは書き換えを返すだけ（`profile/planItemEdit`）で、拡張が 1 つの `WorkspaceEdit` で当てて保存する | ファイルの作成・削除・改名を未保存の変更に混ぜると、参照の置き換え・compile の照合・外での変更の当て直しが複雑になる。中身の編集はこれまでどおり未保存（ADR 005） | 項目の操作も未保存に積み Ctrl+S でまとめて書く。サーバーが直接ファイルを書く |
| 017 | 未保存の変更は当てる順の 1 本の並びにし、並び（マクロの手順・キー、コンボのキー）の中を指す Address は前の変更を当てたあとの位置で数える。並びの外の値は同じ場所の前の変更をその位置で置き換えて畳む | 挿入・削除・移動のあとの位置を一意に決められ、サーバー・ホスト・画面が同じ規則で当てられる。値だけの変更は v0.1 と同じく最後の値が効く | Address ごとの最後の値だけを持つ（v0.1 の形。並びの操作を表せない）。並びを丸ごと置き換える（コメントや書式を保てない。ADR 006） |
